## 4. Architecture and sequence

Add an independently pinned **intelligence release** over one base snapshot; it freezes source/target content hashes, association decisions and method versions. Later condition/prioritization products reference that release and their policies. New permit acquisitions produce new base snapshots, not edits to M7. A release over a newer base is selected explicitly; a GET cannot choose the newest automatically.

This additive overlay is the deliberate extension of ADR-M7-03/07: the one-target M7 match payload cannot encode reviewed many-to-many scope and still preserve old manifest identities. Extra sidecar rows and an additional context ID are accepted in exchange for exact historical replay and no source-payload rewrite. Existing M7 matches/read endpoints remain truthful and usable. An M8 overlay must not make an old M7 capability manifest falsely report planning available; a separate capability response combines implemented stage readiness with the selected release/policy/catalog/input prerequisites.

## 7. Deterministic calculation boundaries and reproducibility

Proposed versions: `road-association-v1`, `road-condition-v1`, `road-recency-v1`, `municipal-estimate-v1`, `maintenance-priority-v1`, `municipal-conflict-screen-v1`, `municipal-scenario-evaluation-v1` and `municipal-ai-evidence-v1`. Version transport separately from policy/catalog parameters. A different source interpretation/rule changes a version or immutable policy hash; never reuse a v1 method name with new semantics.

- **Associations:** pure geometry/topology/code evidence computation in EPSG:32618; explicit scope, candidate tolerances and review. No AI or network. Match quality metrics are not probabilities or physical accuracy.
- **Condition:** accepted scope + applicable policy + valid selected dated evidence → category, or null/unknown/conflict. No interpolation, condition forecast or treatment prescription. Preserve raw decimal scale and timestamps.
- **Age:** explicit as_of_date minus documented source-local inspection date. Policy thresholds and exclusions frozen; retrieval/publication never substitutes for an inspection.
- **Cost:** positive reviewed area × applicable bundled USD/m² rate, ROUND_HALF_UP each line; add non-overlapping rounded allowances; round explicit subtotal×contingency then add. Low/high need documented rate/scenario basis; no inherited demo ±20/30%. Partial known subtotal is not complete cost. Reuse/extract one arithmetic implementation behind compatible v1 wrapper; use source-neutral inputs, not fake Road/RepairOption objects. Timing/lifespan independent and nullable. No savings/rework charge without explicit priced action.
- **Priority:** explicit eligible universe and policy, normalized components and weights; exact Decimal sum, tied ranks and unknown queue. Sorting does not validate urgency or grant project approval. Policy sensitivity is separately saved input, not probabilistic uncertainty.
- **Screening/scenarios:** qualified work evidence + reviewed geometry/time mapping + explicit parameters; half-open civil intervals where valid; indeterminate checks otherwise. Reuse neutral spatial/temporal arithmetic under unchanged legacy wrappers, not a copied engine or official-to-synthetic adapter. Keep admin-window findings distinct from work/hypothetical findings. Scenarios sum complete action costs only, freeze calendars/closures when supplied and never optimize schedules.

Canonical input hashes include base snapshot/full source revision and raw checksum references, complete relevant frozen record contents, accepted association/decision hashes, source/field/unit lineage, policies/catalog/assumptions, declared road/project universe, exclusions, explicit as_of_date, calculation/adapter/contract versions and relevant GIS runtime versions. Sort set-like collections only; preserve geometry coordinate semantics. Hash content before adding self hashes. IDs/output timestamps/request IDs/retrieval attempts excluded from semantic result hashes; actual observation/price/as-of dates remain inputs. Persist input/result hashes plus full inputs, not IDs into mutable sources alone. Replays use only saved inputs; unsupported method/runtime returns incompatibility, never silently computes with current policy. Preserve existing v1 versions/hashes and original runtime metadata.
