# Known limitations and release boundary

Reviewed for M6 on 2026-11-07. No critical or high-severity application crash was found in the tested local workflow. This assessment covers the bounded synthetic demonstrator on the verified host, not production safety, penetration testing or cross-browser certification.

| Priority / scope | Limitation and practical effect |
| --- | --- |
| Release blocker for municipal/production use | Data is entirely authored and synthetic. The 24 schematic segments do not depict actual NYC streets; dimensions, conditions, project footprints, organizations, prices and dates are not municipal observations. No city adoption or accuracy validation is claimed. |
| Release blocker for public deployment | The API is unauthenticated and has no verified identity, roles, tenant isolation or municipal authorization. Loopback binding, explicit CORS, browser-origin guards and payload bounds are demo safeguards only. A local process can still call the API without an Origin header. Do not expose it publicly. |
| Release blocker for engineering use | Unknown utilities/location/depth/coverage never establish safe excavation. Broad shared-road/corridor and approximate footprints can generate false positives; missing or incorrect records can hide issues. No screening finding certifies physical interference or authorizes construction/spending. |
| Medium, planning scope | Synthetic bundled rates and rate sensitivities are planning assumptions, not bids, market validation, probabilities or calibrated confidence bounds. Utility construction, restoration/rework, delay, design and other catalog exclusions are not automatically priced. Coordination has no supported monetary benefit here. |
| Medium, scheduling scope | Five preliminary active/setup/curing days are separate from seven supplied calendar days and lane-closure-days. Calendars are recorded assumptions; weather, work crews, traffic delay, emergency access and actual construction commitments are unmodeled. Deferral always needs qualified review. |
| Medium, AI interpretation | The model selects fact references and fixed templates; it cannot generate unrestricted factual prose. This limits nuance and may decline valid paraphrases. Input completeness, source truth, physical feasibility, fairness, prompt-injection immunity and general entailment are not guaranteed. |
| Medium, AI availability | No paid/live provider call was made; account access, billing and live latency remain unverified. SDK/HTTP mocks cover valid and failed selections, timeout, 429, outage and malformed output. Deterministic no-key fallback was verified in the actual browser. |
| Medium, resource/deployment scope | Bounded ≤30-road/≤50-project demo; dense pair screening can still be quadratic. Bodies are capped at 1 MiB and AI packages/calls are bounded, but there is no general durable HTTP rate limit, distributed quota or production DoS protection. Scenario/history reads and local append-only records can grow; no retention/compaction policy exists. |
| Medium, storage/audit scope | Local SQLite files are not encrypted or tamper-proof. Hashes/replay detect inconsistency, not malicious administrators or truthful measurements. No backup service, disaster recovery, identity-verified review signature or regulatory audit guarantee exists. Interrupted saves may have persisted; estimate POST has no idempotency key. |
| Low, runtime size | MapLibre remains about 1,069 kB raw plus its local 519 kB worker; Vite retains its 500 kB advisory. Lazy splitting reduces the shell to about 273 kB and defers the scenario editor. No mobile CPU/GPU, cold-load or citywide performance guarantee was established. |
| Low, test dependency | Starlette warns about its httpx TestClient adapter. All 212 backend tests pass; a deliberate future dependency update should address it. No lint command exists. Python dependency advisory scanning was not performed; pip check verifies dependency consistency only. |
| Low, browser/accessibility coverage | Actual browser smoke checks covered desktop 1280×720 and mobile 390×844, keyboard road selection, source focus and scrollable comparison. They are not a WCAG audit, screen-reader certification, browser-matrix or 3-second map-readiness benchmark. WebGL requires compatible hardware; the road list is the fallback. |
| Low, editor/history scope | Scenario list initially retrieves histories with per-scenario requests; the UI history request displays the default newest 30 evaluations, while additional history remains available through the API's offset pagination. No estimate listing, forecast, patch/restoration catalog, shared-mobilization adjustment, automatic scheduling, live ingestion or global optimization exists. Unsaved forms remain local and are lost on a full page reload. |
| Low, setup scope | Initial registry access is needed for pinned dependencies. Tests verified macOS 14.5 arm64, Python 3.12.5 and Node 24.5.0; other operating systems were not tested. The startup helper uses POSIX process groups. It creates a fresh retained DB per run rather than deleting/resetting existing data. |

There is no remaining M6 feature backlog required for the local judging workflow. Production readiness and any post-hackathon capabilities require separately scoped work. Do not infer a production release from completion of the hackathon acceptance checklist.
